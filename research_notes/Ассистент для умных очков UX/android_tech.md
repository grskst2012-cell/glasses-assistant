# Android-техника и Material 3 UI для фонового голосового ассистента-компаньона к BT-очкам (Kotlin, Compose, minSdk 31, target 35)

Дата исследования: 2026-11-05. Часть пунктов не удалось проверить по первичным источникам; они вынесены в Inferences/Gaps с пометкой "из общих знаний".

## 1. Фоновая работа на Android 14/15: FGS type microphone, ограничения запуска, Doze, OEM, Tile/Widget/Assistant

### Takeaway
Foreground service типа `microphone` нельзя СОЗДАТЬ из фона (нужен видимый Activity в момент старта), но есть официальные исключения: запуск из действия по уведомлению, виджету, от VoiceInteractionService, из системного компонента, а также отключённая оптимизация батареи. Практическая схема: один раз запустить сервис при открытом приложении и держать его (START_STICKY + уведомление), а повторные запуски делать через Tile/виджет/кнопку в уведомлении (это исключения), либо через роль Assistant.

### Cited Findings
- С Android 14 (API 34) для каждого FGS нужно объявить `android:foregroundServiceType` и разрешение `FOREGROUND_SERVICE_<TYPE>` помимо `FOREGROUND_SERVICE`. Для `microphone`: `FOREGROUND_SERVICE_MICROPHONE` + рантайм-разрешение `RECORD_AUDIO`; константа `ServiceInfo.FOREGROUND_SERVICE_TYPE_MICROPHONE` для `startForeground(id, n, type)`. — [Android Developers: FGS types](https://developer.android.com/develop/background-work/services/fgs/service-types)
- `RECORD_AUDIO` относится к while-in-use: нельзя создать `microphone` FGS, пока приложение в фоне, и нельзя запускать его из `BOOT_COMPLETED`-ресивера (кроме исключений). — [FGS types](https://developer.android.com/develop/background-work/services/fgs/service-types)
- При target >= 14 система проверяет разрешения в момент создания FGS; в фоне получите `SecurityException`. `checkSelfPermission()` в фоне всё равно вернёт GRANTED и не спасает. Нужно вызывать `startForegroundService()`/`bindService()` при видимой Activity, если нет исключения. — [Restrictions on bg start](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)
- Исключения для while-in-use (микрофон работает даже при старте из фона): сервис стартован системным компонентом; через взаимодействие с app widget; через взаимодействие с уведомлением; через PendingIntent от другого видимого приложения; DPC в режиме device owner; приложением, предоставляющим `VoiceInteractionService`; приложением с `START_ACTIVITIES_FROM_BACKGROUND`. — [Restrictions on bg start](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)
- Общие исключения из запрета фонового старта FGS (но НЕ снимают while-in-use для микрофона отдельно): переход из видимого состояния; возможность запускать Activity из фона; высокоприоритетный FCM; действие пользователя с bubble/уведомлением/виджетом/Activity; точный будильник; текущий IME; BOOT_COMPLETED / LOCKED_BOOT_COMPLETED / MY_PACKAGE_REPLACED; Companion Device Manager с `REQUEST_COMPANION_START_FOREGROUND_SERVICES_FROM_BACKGROUND` или `REQUEST_COMPANION_RUN_IN_BACKGROUND`; пользователь отключил оптимизацию батареи; `SYSTEM_ALERT_WINDOW` (при target 15 нужно ещё и видимое overlay-окно). — [Restrictions on bg start](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)
- Для Android 15: приложения с target >= 15 не могут запускать из BOOT_COMPLETED FGS типов dataSync, mediaPlayback, mediaProjection, phoneCall; микрофон при этом и так запрещён из BOOT. — [FGS types](https://developer.android.com/develop/background-work/services/fgs/service-types)
- Для диагностики в Logcat: "Foreground service started from background can not have location/camera/microphone access: service ..." — значит сервис запущен, но микрофон молчит. — [Restrictions on bg start](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)
- Тип `connectedDevice` для взаимодействия с BT-устройствами (требует BLUETOOTH_CONNECT и др.), но он НЕ даёт доступа к микрофону; для постоянной связи с аксессуаром Google советует Companion Device Manager + companion device presence API (держит приложение живым, пока устройство рядом). — [FGS types](https://developer.android.com/develop/background-work/services/fgs/service-types)
- `specialUse` требует `<property android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE">` и проверяется в Play Console; для Play при target >= 14 нужна декларация типов FGS на странице App content. — [FGS types](https://developer.android.com/develop/background-work/services/fgs/service-types)
- Тип `shortService` ~3 минуты, не sticky — для ассистента не подходит. — [FGS types](https://developer.android.com/develop/background-work/services/fgs/service-types)
- dontkillmyapp.com для Nothing OS: страница вернула 404, данных по Nothing OS из первичного источника получить не удалось (см. Gaps).

### Inferences
- Для хобби-приложения (без публикации в Play) надёжная схема: (1) пользователь открывает приложение -> стартует FGS `microphone` (+ при необходимости `connectedDevice`), он живёт сколько нужно; (2) если процесс убит, перезапуск возможен только из исключений: уведомление-кнопка, виджет, Tile (их клик считается действием пользователя; Tile запускает через `startActivityAndCollapse`, а Activity -> FGS - валидный путь), Companion Device Manager presence.
- "Отключить оптимизацию батареи" (`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, разрешение `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) делает приложение исключением для запуска FGS из фона, но НЕ отменяет while-in-use-ограничение микрофона на уровне создания — по формулировке документа исключения из первого списка не снимают второе. Считать, что микрофонный FGS всё равно лучше стартовать из видимого Activity или по кнопке уведомления.
- Роль Assistant / `VoiceInteractionService` — единственный "легальный" путь запускать микрофонный FGS из чистого фона; но для этого приложение должно стать системным ассистентом по умолчанию (пользователь выбирает в Настройки -> Приложения -> Ассистент), и тогда оно заменит Gemini на long-press кнопки питания/жеста. Для хобби-приложения возможно, но это тяжёлая интеграция (VoiceInteractionService + VoiceInteractionSessionService + `android:permission="android.permission.BIND_VOICE_INTERACTION"`, метаданные `voice-interaction-service`). Из общих знаний, не проверено в этом сеансе.
- Из общих знаний (не проверено здесь): Quick Settings Tile — `TileService` (API 24+), с Android 13/API 33 можно добавить через `StatusBarManager.requestAddTileService`; `onClick` -> `startActivityAndCollapse(PendingIntent)` (с API 34 требуется версия с PendingIntent). Виджет — Jetpack Glance (`androidx.glance:glance-appwidget`, 1.1.x стабилен; точную последнюю версию не проверял) с `actionStartService`/`actionStartActivity`. Кнопки уведомления - PendingIntent на сервис/BroadcastReceiver.
- Нужно закладывать: Doze не влияет на уже работающий FGS с активным AudioRecord, но сетевые вызовы в Doze ограничены, а OEM-убийцы (Nothing OS близок к AOSP, обычно мягче Xiaomi/Huawei, но агрессивная "Battery optimization / Background restrictions" в настройках есть — не проверено) могут убить процесс; поэтому: START_STICKY, `onTaskRemoved`, WorkManager как страховка (не для микрофона), `AlarmManager.setExactAndAllowWhileIdle` не нужен.

### Gaps
- Официально подтверждённого описания поведения Nothing OS (Battery optimization, "Background app management") не найдено: dontkillmyapp.com/nothing вернул 404.
- Не проверены в этом сеансе по первичным источникам: детали TileService (Android 14 `startActivityAndCollapse(PendingIntent)`), текущая версия Glance, ACTION_VOICE_COMMAND/ROLE_ASSISTANT/`RoleManager.ROLE_ASSISTANT` детали. Нужна отдельная проверка на developer.android.com перед реализацией.
- Не проверено, считается ли у Android 15+ микрофонный FGS, стартованный из Tile-клика, исключением (по логике — да, т.к. Tile открывает Activity).

## 2. Wake word на русском (кастомные слова)

### Takeaway
Для хобби-приложения одного разработчика реалистичнее всего: Vosk small-ru с grammar-режимом (JSON-список фраз + "[unk]") как lightweight keyword spotter, либо sherpa-onnx KWS (open-vocabulary, но готовой русской KWS-модели не найдено). Porcupine поддерживает русский, но по сообщению с форума бесплатный тариф закрыт с 30.06.2026 — нужно проверять самому. Цикл `SpeechRecognizer` для wake word не подходит. Дополнительно: wake word можно заменить кнопкой на очках (media button) и Tile.

### Cited Findings
- Документация Android: реализация `SpeechRecognizer` "likely to stream audio to remote servers... not intended to be used for continuous recognition, which would consume a significant amount of battery and bandwidth". — [SpeechRecognizer reference](https://developer.android.com/reference/android/speech/SpeechRecognizer)
- `SpeechRecognizer.createOnDeviceSpeechRecognizer(context)` и `isOnDeviceRecognitionAvailable()` добавлены в API 31 (то есть доступны на вашем minSdk 31, а не только 33); бросает `UnsupportedOperationException`, если on-device недоступен. `checkRecognitionSupport` и `triggerModelDownload` — API 33; `triggerModelDownload` с `ModelDownloadListener` — API 34; ошибки `ERROR_LANGUAGE_NOT_SUPPORTED`/`ERROR_LANGUAGE_UNAVAILABLE` — API 31; `ERROR_TOO_MANY_REQUESTS` — API 31. После `stopListening()` нужно дождаться `onResults`/`onError`, иначе новый `startListening` отклоняется (`ERROR_RECOGNIZER_BUSY`). Вызывать только с main thread. — [SpeechRecognizer reference](https://developer.android.com/reference/android/speech/SpeechRecognizer)
- Vosk, русские модели: `vosk-model-small-ru-0.22` — 45 МБ, "lightweight wideband model for Android/iOS and RPi", WER: 22.71 (openstt audiobooks), 31.97 (openstt youtube), 29.89 (sova devices), 11.79 (golos crowd); большие: `vosk-model-ru-0.42` 1.8 ГБ (WER 4.5-36.0 в зависимости от набора), `vosk-model-ru-0.22` 1.5 ГБ. Лицензия Apache 2.0. Small-модели обычно позволяют динамически менять словарь, большие статичны (для русской small отдельно не указано). — [Vosk models](https://alphacephei.com/vosk/models)
- Porcupine: в списке языков (по README форка репозитория) есть русский; на сайте Picovoice кастомная фраза тренируется "за секунды". Сообщение на форуме Home Assistant (вторичный источник): Picovoice уведомил, что Free Tier будет закрыт 30.06.2026, ключи AccessKey отключатся, некоммерческого тарифа не планируется. — [Porcupine GitHub](https://github.com/Picovoice/Porcupine); [HA community](https://community.home-assistant.io/t/porcupine-free-tier-shutdown-alternatives-for-home-assistant-voice-users/1012382)
- sherpa-onnx KWS: open-vocabulary, ключевые слова задаются файлом токенов + boost score + threshold (пример `▁HE LL O ▁WORLD :1.5 #0.35`), конвертация `sherpa-onnx-cli text2token`, есть готовые Android-APK для KWS. Русская KWS-модель в поиске не найдена; в списке есть русские ASR-модели (например `sherpa-onnx-zipformer-ru-2024-09-18`). — [sherpa-onnx KWS docs](https://k2-fsa.github.io/sherpa/onnx/kws)
- openWakeWord: можно обучать свои модели (синтетические TTS-примеры), экспорт в .onnx/.tflite (~200 КБ); для русского специфичных материалов не найдено; датасет ACAV100M под CC-BY-NC-SA-4.0 — обученные модели наследуют некоммерческое ограничение. HA Android использует другое решение (microWakeWord). — [HA community tool](https://community.home-assistant.io/t/tool-openwakeword-train-train-your-own-wake-words-locally-tts-examples-real-mic-negatives-onnx-tflite-export/1026289)

### Inferences
- Рекомендация (с оговоркой, что это моё суждение): 
  1. MVP без wake word: триггеры = кнопка очков (MediaSession), Tile, виджет, кнопка в уведомлении. Это избавляет от постоянного прослушивания и от while-in-use проблем.
  2. Если нужен голосовой wake word: Vosk small-ru в grammar-режиме (`Recognizer(model, rate, "[\"привет ассистент\", \"[unk]\"]")`), постоянный AudioRecord 16 кГц в FGS microphone, затем переход в полноценный STT. Плюсы: Apache 2.0, русский, 45 МБ, любое слово без обучения. Минусы: ложные срабатывания выше специализированных KWS, нагрузка на CPU постоянная (оценка расхода батареи не найдена - измерять самому).
  3. Порцупин: качество лучше всего, но риск с лицензией/ключами после 30.06.2026; не закладывать как основу без проверки текущих условий.
  4. sherpa-onnx KWS и openWakeWord: интересны, но под русский нет готовых моделей - требуются эксперименты (токенизация кириллицы под выбранную ASR-модель для sherpa; обучение на русских TTS-примерах для oWW). Для одного разработчика трудозатраты выше.
- Цикл `SpeechRecognizer` для wake word: плохо — по доке не рассчитан на непрерывное использование, при онлайн-режиме идёт стриминг на сервер; на практике (из общих знаний, не проверено здесь) каждое перезапускание даёт сигналы/звуки и ошибки `RECOGNIZER_BUSY`/`NO_MATCH`; на BT-гарнитуре ещё и пересоздаёт SCO. Whisper.cpp — не для wake word (слишком тяжёлый для постоянной работы), годится для финального STT офлайн (не исследовал качество на русском).

### Gaps
- Нет проверенных данных по расходу батареи Vosk/sherpa/Porcupine в режиме постоянного прослушивания.
- Не найден официальный анонс Picovoice о закрытии Free Tier; только пост на форуме (вторичный источник). Текущие цены не проверены.
- Не подтверждено наличие русской KWS-модели для sherpa-onnx и русского обучения для openWakeWord.
- `EXTRA_PREFER_OFFLINE` не проверялся в этом сеансе.

## 3. STT/TTS на русском, маршрутизация аудио на BT-очки, кнопка очков как триггер

### Takeaway
Для офлайн STT на русском лучший баланс на телефоне: sherpa-onnx с русской zipformer (или Vosk big - не для телефона); онлайн лучше системный Google. Для TTS: системный Google TTS как базовый, sherpa-onnx VITS/Piper — офлайн-вариант. Для маршрутизации на BT-гарнитуру на API 31+ использовать `AudioManager.setCommunicationDevice()`, а не устаревший `startBluetoothSco()`.

### Cited Findings
- `startBluetoothSco()` помечен deprecated, замена — `AudioManager#setCommunicationDevice(AudioDeviceInfo)`. — [Android reference mirror (Xamarin)](https://developer.xamarin.com/api/member/Android.Media.AudioManager.StartBluetoothSco()/)
- AOSP описывает `setCommunicationDevice` как основную точку управления для запуска SCO-соединения (документ про новую архитектуру audio-managed SCO). — [AOSP SCO management](https://source.android.com/docs/core/audio/sco-audio-mgmt)
- Отчёт одного стороннего VoIP-проекта (анекдот, не официально): на API 31+ использует `setCommunicationDevice`, на старых — `startBluetoothSco` + `setBluetoothScoOn`; `setBluetoothScoOn()` молча игнорируется на Android 12+ для несистемных приложений; устаревшие API на тестовых устройствах работали до API 35. — [wz-phone commit](https://git.manko.yoga/manawenuz/wz-phone/commit/300ea66d138ad13e5526aac0dde1f53e012df196.diff)
- Meta Wearables Device Access Toolkit: камера доступна через SDK, а микрофон и динамики — через стандартные Bluetooth-профили iOS/Android; "Hey Meta"/Meta AI в тулкит не входят. — [Meta FAQ](https://developers.meta.com/wearables/faq); (формулировка из первого поиска, который цитировал FAQ)
- Модели Meta Wearables FAQ: Ray-Ban Meta (Gen 1 и Gen 2), Meta Ray-Ban Display, Oakley Meta HSTN, Oakley Meta Vanguard; платформы iOS и Android с теми же требованиями ОС, что у приложения Meta AI; SDK скачивается по всему миру, но полные возможности ограничены странами, где поддерживаются AI-очки; Device Access Toolkit 1.0 стабильный, раскатка с 30 сентября 2026; приём заявок на публикацию ещё не открыт (по FAQ на момент чтения); спаривание очков только через приложение Meta AI. — [Meta FAQ](https://developers.meta.com/wearables/faq)
- Более ранний вариант FAQ (поиск): публикация интеграций ограничена выбранными партнёрами на период превью, ожидалась для широкой аудитории в 2026; доступ к дисплею вне объёма. — [Meta FAQ via search](https://developers.meta.com/wearables/faq); [Road to VR](https://roadtovr.com/meta-ray-ban-smart-glasses-third-party-app-sdk-device-access-toolkit/)
- Piper (MIT) имеет русский голос "Denis" (по стороннему каталогу); приложение VoxSherpa на sherpa-onnx запускает Piper/VITS офлайн на Android 11+ ARM64, заявляет русский (самоотчёт). — [tts.ai Piper](https://tts.ai/voices/piper/); [VoxSherpa](https://github.com/CodeBySonu95/VoxSherpa-TTS)
- Сторонние страницы по Ray-Ban Meta (розница, гайды по доступности) называют очки обычным Bluetooth-аудиоустройством и поддерживают Android 10+ для Gen 2; детали HFP/AVRCP/long-press для сторонних приложений не найдены. — [Floridareading guide](https://floridareading.com/blogs/news/how-to-connect-ray-ban-meta-smart-glasses-to-mobile-screen-readers-a-complete-pairing-guide)

### Inferences
- Схема маршрутизации (из общих знаний + найденного): `AudioManager.getAvailableCommunicationDevices()` -> выбрать `TYPE_BLUETOOTH_SCO` (или `TYPE_BLE_HEADSET` на API 31+ для LE Audio) -> `setCommunicationDevice(device)` -> открыть `AudioRecord` с `MediaRecorder.AudioSource.VOICE_COMMUNICATION` (или MIC) и `setPreferredDevice()`; после — `clearCommunicationDevice()`. Режим `MODE_IN_COMMUNICATION` на время диалога. SCO даёт 8/16 кГц (CVSD/mSBC) — качество STT ниже, чем с телефонного микрофона; это ключевой компромисс: можно слушать с микрофона очков (удобно) или телефона (лучше качество). Не проверено, какие кодеки у Ray-Ban Meta.
- TTS в очки: пока идёт SCO-сессия, TTS идёт через "звонковый" канал (узкая полоса); без SCO — через A2DP (качество выше, но микрофон недоступен). Возможна стратегия: слушаем по SCO, отвечаем после закрытия SCO через A2DP (с задержкой переключения профилей ~сотни мс - оценка, не измерено).
- Streaming TTS по предложениям: разбить ответ LLM на предложения, ставить в очередь `TextToSpeech.speak(..., QUEUE_ADD, ...)` с `UtteranceProgressListener`, либо свой плеер для sherpa-onnx (генерация предложения в фоновом потоке, `AudioTrack` в режиме stream). Audio focus: `AudioFocusRequest` с `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` и `USAGE_ASSISTANT` (из общих знаний, API не проверялся здесь).
- Триггер от кнопки очков: система отправляет media button события активной `MediaSession` (AVRCP play/pause и др.). Создать `MediaSession` (androidx.media3 `MediaSession` или `MediaSessionCompat`), держать её активной с пустым плеером/тишиной, обрабатывать `onMediaButtonEvent`. Long-press на самих очках у Ray-Ban Meta, вероятнее всего, зарезервирован под Meta AI/съёмку, а не AVRCP — НЕ проверено; нужен эксперимент с реальными очками (логировать входящие `KeyEvent`).
- Meta Wearables Toolkit для голосового ассистента малополезен: микрофона через SDK нет (используется обычный BT), "Hey Meta" недоступен; ценность — камера (для "что я вижу"). Публикация ограничена, но личное использование разработчиком возможно (по описанию превью; детали регистрации не проверены).

### Gaps
- Не найдено сравнительных данных WER для русского: Google online vs on-device vs sherpa-onnx zipformer-ru vs Whisper. Надёжных бенчмарков нет в собранном.
- Яндекс SpeechKit и Silero TTS: ничего не исследовано в этом сеансе (лимит запросов); известно лишь из общих знаний, что SpeechKit — облачный платный, Silero — офлайн, лицензия модели требует проверки (CC BY-NC? не проверено).

## 4. Material 3 / Expressive для Compose

### Takeaway
Expressive-компоненты (LoadingIndicator, ButtonGroup, FloatingToolbar, WavyProgressIndicator, MaterialExpressiveTheme) в стабильной `material3:1.4.0` (24.09.2025) НЕ публичны: из 1.4.0-beta01 удалены все API с `ExperimentalMaterial3ExpressiveApi`. Они живут в линейке 1.5.0; на 05.11.2026 актуален `1.5.0-rc01` (04.11.2026). Для нового приложения брать 1.5.0 (RC/ближайший стабильный).

### Cited Findings
- Стабильная версия `androidx.compose.material3:material3` = 1.4.0 (24.09.2025); RC 1.5.0-rc01 — 04.11.2026; 1.5.0-beta02 — 21.10.2026; 1.5.0-alpha29 — 23.09.2026. — [Release notes](https://developer.android.com/jetpack/androidx/releases/compose-material3)
- 1.4.0-beta01 (30.07.2025): "All public APIs tagged with `ExperimentalMaterial3ExpressiveApi` ... have been removed, please switch to `1.5.0-alpha` to continue enjoying these features." 1.4.0 добавил `MotionScheme` для компонентов и изменил анимацию indeterminate circular progress. — [Release notes](https://developer.android.com/jetpack/androidx/releases/compose-material3)
- Продвижение API в 1.5.0 alpha: alpha18 — `WavyProgressIndicator`, `materialExpressiveTheme`/`expressiveLightColorScheme` стабильны, добавлена аннотация `Material3ExpressiveApi` без OptIn; alpha19 — FAB/FAB menu и expressive-кнопки стабилизированы, но продвижение `MaterialShapes` и `LoadingIndicator` в стабильные было откатено; alpha22 — `ButtonGroup` и expressive `FloatingToolbar` стабильны; alpha23 — expressive-элементы списков, `TopAppBar`/`FlexibleBottomAppBar` без OptIn; alpha24 — новая библиотека `material3-ripple`; alpha25 — `BasicAlertDialog` стабилен, `TonalToggleButton` переименован в `FilledTonalToggleButton`; alpha28 — удалены старые перегрузки `ToggleButton`; alpha29 (breaking) — у `Slider`/`RangeSlider` `onValueChange` обязателен и предпочитается `SliderState`. — [Release notes](https://developer.android.com/jetpack/androidx/releases/compose-material3)
- Список expressive-компонентов (индекс Compose): ButtonGroup, LoadingIndicator, ContainedLoadingIndicator, FlexibleBottomAppBar, HorizontalFloatingToolbar, VerticalFloatingToolbar, SplitButtonLayout и др. — [composables.com](https://composables.com/material-3-expressive)
- Единственный источник, утверждающий детали 1.5.0-alpha26 (LoadingIndicator всё ещё требует opt-in), — стороннее "skill"-описание, непроверено; по официальным заметкам на alpha19 стабилизация LoadingIndicator откатывалась. — [Skill guide](https://playbooks.com/skills/fumiya-kume/toy-poodle-love/m3-expressive)
- Статьи по M3 Expressive в Compose (описывают alpha14-эру): [ProAndroidDev part 1](https://proandroiddev.com/material-3-expressive-design-a-new-era-9ea77959a262), [part 2](https://proandroiddev.com/material-3-expressive-design-a-new-era-part-2-6a93483c98b0).

### Inferences
- Подбор компонентов для голосового приложения (мои рекомендации, не из источников):
  - Индикатор состояния (waiting / listening / thinking / speaking): кастомный Canvas-"орб" с `animateFloatAsState`/`rememberInfiniteTransition`, цвета из `MaterialTheme.colorScheme` (primary/tertiary/secondary по состояниям); для thinking — `LoadingIndicator` (морфирующие `MaterialShapes`) как готовая expressive-замена; `WavyProgressIndicator` — для прогресса загрузки моделей Vosk/sherpa.
  - Транскрипт: `LazyColumn` с `reverseLayout`, пузырьки на `surfaceContainer*`; `Modifier.semantics { liveRegion = LiveRegionMode.Polite }` для последнего сообщения (TalkBack).
  - Быстрые подсказки: `SuggestionChip`/`AssistChip`; переключение режима (например, "тихий/голос"): `SingleChoiceSegmentedButtonRow` или expressive `ButtonGroup` с `ToggleButton`.
  - Панель действий: `HorizontalFloatingToolbar` или `FloatingActionButton` большого размера (96 dp в expressive) для push-to-talk.
  - Навигация: приложение из 1-2 экранов — один основной экран + настройки через `ModalBottomSheet`/отдельный route; NavigationBar не нужен при <3 разделов.
  - Haptics: `LocalHapticFeedback.current.performHapticFeedback(HapticFeedbackType.…)` (в Compose 1.6+ типы вроде `ContextClick`, `Confirm`, `Reject` - из общих знаний, версии не проверены) на старт/конец прослушивания.
  - Dynamic color: `dynamicDarkColorScheme/LightColorScheme(context)` (API 31+ — подходит под minSdk 31); `MaterialExpressiveTheme(motionScheme = MotionScheme.expressive())`.
  - Доступность: touch target >= 48 dp, учитывать font scale до 200% (избегать фиксированных высот), `contentDescription` на орбе с состоянием, озвучка смены состояния через `liveRegion`/`announceForAccessibility`, уважать "Remove animations" (`Settings.Global.ANIMATOR_DURATION_SCALE`) - всё из общих знаний.
- Зависимости (ориентир): BOM для Compose, затем явная версия `androidx.compose.material3:material3:1.5.0-rc01` (или стабильная 1.5.0, если выйдет) — тянуть именно её, а не BOM-версию, если BOM всё ещё указывает 1.4.0. Это моё предположение: соответствие BOM не проверялось (стороннее утверждение про "BOM 2026.08.00" не подтверждено).

### Gaps
- Не проверена официальная страница m3.material.io по Expressive (гайды по motion, размерам, состояниям "voice/assistant").
- Не проверены текущие версии `androidx.glance`, `androidx.media3`, Compose BOM.
- Нет данных по спецификации Expressive для "голосовых" паттернов (орб/волна) - это кастомный дизайн.
- Подтверждение того, остались ли какие-то expressive API (в т.ч. `LoadingIndicator`) под `@ExperimentalMaterial3ExpressiveApi` в 1.5.0-rc01, не получено; проверять в IDE.
